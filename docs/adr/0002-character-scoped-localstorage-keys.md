# localStorage をキャラ単位のキーに分割し、IndexedDB へは移らない

装備1件ごとにツールチップのサムネイル（JPEG q0.82）を持つため、1キャラ20装備で約0.5MB を消費する。localStorage の 5MiB 上限に対し、Character を複数持てば容量が現実的な制約になる。IndexedDB への移行（容量制限が実質消える）と、単一キーに全キャラをネストする案（実装最小）も検討したが、**localStorage のまま、キーを `mtc:char:<id>:*` の形でキャラ単位に分割する**ことを選んだ。単一キー案は装備を1件取り込むたびに全キャラ分をシリアライズし直すため、キャラが増えるほど目に見えて遅くなる。IndexedDB は正しい方向だが、ストレージ層・スナップショット・エクスポート/インポートを巻き込む書き直しで、Character 導入とは独立にいつでも実施できるため今回のスコープから外した。

容量使用率は管理画面に表示し、上限が近づいたら警告する。

## Consequences

- エクスポート形式は `version: 3` とし、`characters: [...]` + 全体共有の `userbank` を持つ。
- インポートは常に非破壊とする。旧 `version: 2` のファイルは**新規 Character として着地**させ、既存キャラには一切触れない。v3 はキャラIDが一致すればそのキャラへマージ、無ければ新規追加。インポートには取り消し手段がなく、アクティブキャラへマージすると装備が混線して手作業の分離がほぼ不可能になるため。
- 既存データ（キャラ概念なしの `mtc:items` 等）は起動時に自動で「キャラ1」1件へ移行する。移行を促すダイアログは出さない。読まずに閉じられると「開いたら装備が消えた」という最悪の体験になるため、何もしなくても従来通り動くことを優先する。
